# Sprint 3.3: Save/Load в середине рана

> **For Hermes:** TDD (RED → GREEN → commit) на каждый Task. Foundation (RunState +
> SaveService.save_run/load_run + SaveSvc.run_path + versioning) уже есть из S1.x.
> Не хватает только: (1) pointer на активный ран в MetaProfile, (2) save в середине
> рана (а не только на _end_run), (3) resume логика в RunController.

**Goal:** Игрок может закрыть игру в любой момент (между боями, посреди PREP-фазы)
и продолжить с того же места. «Continue» = загрузить последний активный ран.

**Architecture:**
- `MetaProfile.current_run_seed: int = 0` — pointer на активный ран (0 = нет активного)
- `SaveService.has_run(seed)`, `SaveService.delete_run(seed)`, `SaveService.get_current_run_seed(profile)`
- `RunController.save_now()` — сохранить state + обновить `profile.current_run_seed`
- `RunController.resume_run(seed)` — загрузить RunState из диска, заменить `self.state`, продолжить с PREP
- Auto-save хуки: после `_on_battle_ended` (любой исход), в `_enter_reward`, в `start_run`
- `GameBus.emit_run_saved(seed)` signal для UI (S4.x)

**Tech Stack:** GDScript 2.0, Godot 4.7, TDD, single source of truth в `core/balance.gd`.

## Архитектурные решения

### D1: Pointer на активный ран

**Выбор:** `MetaProfile.current_run_seed: int = 0`. Один активный ран в момент времени.

**Почему:**
- Singleplayer roguelike — не нужны параллельные раны
- Простой API: `profile.current_run_seed = state.seed` при save
- Resume через `RunController.resume_run(profile.current_run_seed)`
- При `_end_run()` → `current_run_seed = 0` (ран закончен)

### D2: Когда auto-save?

**Выбор:** В трёх местах:
1. `start_run(seed)` — после создания нового state, ДО первого боя
2. `_on_battle_ended()` — после любого исхода (win/lose), ДО перехода в PREP/REWARD
3. `_enter_reward()` — после генерации offer (на случай если игрок выберет позже)

**Почему:**
- Save после боя — самое частое состояние "игрок закрыл игру"
- Save в PREP перед выбором — гарантирует, что state.unit_ids совпадает с диском
- Save в start_run — для самого первого запуска (если игрок сразу закроет)

### D3: resume vs start_run

**Выбор:** Новый метод `resume_run(seed)`. НЕ трогаем `start_run()` (он всегда создаёт новый).

**Почему:**
- `start_run()` семантика = «начать новый ран» — менять её опасно (ломает существующие тесты)
- `resume_run()` — отдельный явный метод, невозможно случайно
- Resume = load_run + присвоить state + emit signal + перейти в PREP

### D4: Save во время BATTLE — да или нет?

**Выбор:** **НЕТ**. Save только в PREP/REWARD/GAMEOVER. BATTLE не сейвится.

**Почему:**
- BATTLE — тиковый цикл с быстро меняющимся HP/cooldowns. Сохранение каждую секунду = overhead
- Если игрок закроет игру во время боя — это OK, бой переигрывается с начала (но state.unit_ids сохранился)
- Реализация: save в `_on_battle_ended` (когда `runner.state.phase == ENDED`), не во время `step()`

### D5: resume без сохранённого рана

**Выбор:** `resume_run(seed)` возвращает `false`. Никаких ошибок, state не меняется.

**Почему:**
- Graceful degradation — UI может проверять через `SaveService.has_run(seed)`
- Если seed=0 — `false` (current_run_seed == 0 → нечего продолжать)
- Если file missing — `false`

### D6: delete save на _end_run

**Выбор:** При `_end_run(won=false)` — НЕ удаляем save (игрок может посмотреть итоги). При `won=true` — НЕ удаляем тоже (статистика рана в профиле).

**Почему:**
- Save = backup. Удалять = риск потерять статистику при crash
- UI позже покажет список ран-попыток (S4.x)
- Если игрок хочет удалить — отдельный UI action (не в S3.3)

## Проверяет, существует ли файл сохранения для этого seed.
static func has_run(seed_value: int) -> bool:
    if seed_value == 0:
        return false
    return FileAccess.file_exists(SaveSvc.run_path(seed_value))


## Удаляет файл сохранения. Возвращает true если файл был удалён.
static func delete_run(seed_value: int) -> bool:
    if seed_value == 0:
        return false
    var path: String = SaveSvc.run_path(seed_value)
    if not FileAccess.file_exists(path):
        return false
    var dir: DirAccess = DirAccess.open(SaveSvc.RUNS_DIR)
    if dir == null:
        return false
    return dir.remove(path.get_file()) == OK


## Возвращает seed активного рана из MetaProfile (0 если нет).
static func get_current_run_seed(profile: MetaProfile) -> int:
    if profile == null:
        return 0
    return profile.current_run_seed


## Проверяет, есть ли активный ран и существует ли файл для него.
## Используется UI для кнопки "Continue".
static func has_active_run(profile: MetaProfile) -> bool:
    if profile == null or profile.current_run_seed == 0:
        return false
    return has_run(profile.current_run_seed)


## S3.3: список всех сохранённых ранов (по seed). Используется для UI browse.
## Возвращает Array[int].
static func list_runs() -> Array[int]:
    var result: Array[int] = []
    var dir: DirAccess = DirAccess.open(SaveSvc.RUNS_DIR)
    if dir == null:
        return result
    for fname in dir.get_files():
        if not fname.begins_with("run_") or not fname.ends_with(".tres"):
            continue
        # run_<seed>.tres → seed
        var seed_str: String = fname.substr(4, fname.length() - 9)
        if seed_str.is_valid_int():
            result.append(int(seed_str))
    return result
```

## S3.3: сохраняет текущий state + обновляет profile.current_run_seed.
## Вызывай вручную (кнопка "Save") или из auto-save хуков.
## Возвращает true если сохранено успешно.
func save_now() -> bool:
    if state == null or state.seed == 0:
        GameLog.warn("run", "save_now: no active state")
        return false
    var ok: bool = SaveService.save_run(state)
    if ok and profile != null:
        profile.current_run_seed = state.seed
        SaveService.save_meta(profile)
        GameBus.emit_run_saved(state.seed)
        GameLog.info("run", "Run saved", {"seed": state.seed, "round": state.round_index})
    return ok


## S3.3: сбрасывает active run marker (вызывается при _end_run).
func _clear_active_run() -> void:
    if profile != null and profile.current_run_seed != 0:
        profile.current_run_seed = 0
        SaveService.save_meta(profile)
```

**Step 2:** В `run_controller.gd` добавить:
```gdscript
## S3.3: загружает RunState из диска по seed и продолжает ран с PREP фазы.
## Возвращает true если state загружен успешно.
## НЕ пересоздаёт state — заменяет self.state на загруженный.
## Если файла нет — возвращает false, state остаётся прежним.
func resume_run(seed_value: int) -> bool:
    if seed_value == 0:
        GameLog.warn("run", "resume_run: seed == 0")
        return false
    var loaded: RunState = SaveService.load_run(seed_value)
    if loaded == null:
        GameLog.warn("run", "resume_run: no save for seed", {"seed": seed_value})
        return false
    state = loaded
    # Rng восстанавливаем из seed для детерминизма (на случай если seed_run не звался).
    Rng.seed_run(state.seed)
    # Shop перегенерируем (transient — был утерян при restart).
    _refresh_shop()
    _set_phase(Phase.PREP)
    if profile != null:
        profile.current_run_seed = state.seed
    GameBus.emit_run_resumed(state.seed)
    GameLog.info("run", "Run resumed", {"seed": state.seed, "round": state.round_index})
    return true
```

## Риски

| Риск | Митигация |
|---|---|
| R1: Auto-save в `_on_battle_ended` перезаписывает state — если игрок близко к close, может быть потерян последний тик | Save происходит ПОСЛЕ окончания боя, не во время — это безопасно |
